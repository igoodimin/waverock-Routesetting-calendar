# 현재 상태

## 완료
- 사용자 승인 범위로 브라우저용 정적 웹 앱 구현: 세 지점 통합 달력, 고정 5주, 날짜 드래그 생성, 섹터명·기간·시간·문구 편집, 삭제, 중복 카드 적층, localStorage 자동 저장·복원.
- 제공 배경·SVG 로고 및 설치된 Arial Black/Pretendard 폰트 사본을 사용한다. 원본 자료는 변경하지 않았다.
- PNG 추출 코드: 1080×1350 디자인을 2160×2700px로 렌더링하고 150dpi pHYs 메타데이터를 기록한다.
- 사용자가 승인한 수요일 월말 예외를 적용해 인접 월 날짜 누락을 수정했다.

- 2026-10-12 승인된 시각 수정: 하루(한 칸) 카드 섹터명 21px, 작은 SVG의 로고 크기 35px·위치와 섹터명 시작 위치 반영. 여러 날 카드는 22px 유지. 중복 적층 시 기존 비례 축소 유지.
- 지점별 배경색을 SVG와 일치시킴: 남천 #2b2b2b, 서면 #287338, 부산대 #245fab. 원본 SVG에서 크기별 로고 6개를 추출하여 지점별 로고 색상 적용, 범례 동기화.

- 2026-10-12 추가 승인 반영: 날짜 클릭·드래그 시 일정 지정 팝업을 열고 저장 시 생성. 닫기·Escape 취소 시 생성하지 않음. 기존 일정 수정 팝업을 공용으로 사용하며 신규 생성 시 삭제 버튼 숨김.
- 하루(한 칸) 카드는 로고 오른쪽에서 섹터명(21px)·시간을 중앙정렬하고 안내 문구를 표시하지 않음.

- 2026-10-12 추가 승인 반영: 하루(한 칸) 카드 섹터명 기준선을 2px 아래로 이동(중복 적층 시 비례 축소). 일정 팝업에 기존 지점별 목록을 사용하는 섹터 드롭다운과 직접 입력을 함께 제공. 지점 변경 시 목록을 갱신하되 입력한 섹터명은 보존하며, 목록에 없는 이름은 직접 입력으로 표시.

## 검증 결과
- 이전 구현의 `npm test`: 6개 모두 통과. 이후 UI 수정에 대한 재실행 결과는 아님.
- 1900~2200년 모든 월의 일요일 시작·연속 35칸·인접 월을 포함한 날짜 누락 없음 검증 통과.
- 수요일 월말과 연도 경계 회귀 검사, 주 경계 카드 분할·중복 적층, 날짜 유효성 및 PNG 150dpi 메타데이터·CRC 검증 통과.
- 색상 수정 시 `node --check app.mjs`: 통과. 이후 팝업·섹터 선택 수정에서는 재실행하지 않음.
- 2026-10-12 사용자가 브라우저·실제 PNG 확인을 완료했고 PNG 저장이 좋다고 평가했다.
- 이전 색상 수정: app.mjs·calendar.mjs 문법 검사 통과. 3개 지점 × 하루·여러 날 렌더링 함수 검사(배경색, 로고 선택·크기, 폰트) 통과. 로고 6개 원본 경로·색상 일치 및 SVG XML 검사 통과. 기존 npm test 6개는 이전 검증 결과이며 이번 시각 수정에서는 재실행하지 않았다.

- 팝업 생성·중앙정렬 수정은 사용자가 검증하고 수락했다.
- 섹터 선택·직접 입력 및 2px 위치 수정은 사용자 요청으로 에이전트 검증을 실행하지 않았다. 사용자가 마지막 결과에 “좋아”라고 응답하고 세션 종료를 요청하여 수락 완료. 마지막 수정의 구체적인 검증 항목·결과는 별도로 보고되지 않았다.

- 목표: GitHub에 소스를 올리고 누구나 사용할 수 있는 웹으로 배포. 아직 커밋·업로드·웹 배포는 하지 않았다. 종료 시 `git status --short`에서 프로젝트 파일 전부 미추적 상태 확인.

- Supabase 공용 저장 코드 반영: 일정별 REST CRUD, 버전 비교 충돌 처리, 10초 주기 조회, 편집 팝업 중 조회 보류. config.mjs에 사용자 제공 프로젝트 URL과 공개용 Publishable key 반영.
- 사용자가 로그인 없이 누구나 조회·추가·수정·삭제하는 단일 공용 달력을 명시적으로 승인했다.
- SQL 오류 원인: Query source가 Logs였다. Database로 전환하고 calendar_events 미존재(NULL) 확인 후 supabase/schema.sql 실행. `Success. No rows returned`로 테이블·공개 CRUD 정책·버전 검사 트리거 생성 완료 확인.
- 기존 로컬 일정은 브라우저의 waverock.calendar.v1에 보존하며 공용 서버에 자동 이관하지 않았다. 선택 연월·지점만 새 로컬 키에 저장한다.
